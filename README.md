# Online reachability

Reachset-aware sampling MPC for autonomous racing. The planner rolls sampled
controls through interval reachable sets and scores them before committing a
control; the experiments measure how that changes safety and lap time in the
Buzzracer simulator and on the DualGuard-MPPI benchmark.

For a short overview and hardware videos, please visit the
[project website](https://3cm2vcvv.github.io/2026-RAL-sampling/).

## Layout

```
core/                     the contribution
  immrax_planner.py       dimension-agnostic reachset-aware planner
  immrax_controller.py    Buzzracer CarController adapter over the planner
  reachset_cost.py        rollout cost evaluators (point, vertices, exhaustive)
  disturbance.py          one disturbance box shared by planner and plant
  immrax_dynamic_bicycle_cartesian.py, immrax_dubins_car.py
  replay_controller.py    replays logged controls and renders reachsets

experiments/              one directory per DVC experiment
  shared/                 cross-experiment helpers (track/XML/analysis/seed)
  reachset_sweep/         the 1080-combo sweep + crash inspection
  controller_sweep/       Immrax vs Shield-MPPI across tracks/disturbances
  dualguard_rc/           DualGuard-MPPI Section VI RC-car comparison
  dualguard_mppi/         DualGuard-MPPI baseline (own dvc.yaml)
  reachset_recording/     hardware run -> reachset replay -> video overlay

outputs/                  generated by the pipelines (not included)
data/                     stage inputs to supply before running (not included)
vendor/                   vendored checkouts: Buzzracer, immrax, Shield-MPPI
```

## Experiments

| Pipeline | Code | Output |
|---|---|---|
| `reachset_sweep` | `experiments/reachset_sweep/` | `outputs/reachset_sweep/{runs,analysis,crashes}` |
| `controller_sweep` | `experiments/controller_sweep/` | `outputs/controller_sweep/{runs,analysis,track_fixtures}` |
| `dualguard_rc` | `experiments/dualguard_rc/` | `outputs/dualguard_rc/{runs,analysis,warehouse_track.npz}` |
| `dualguard_mppi` | `experiments/dualguard_mppi/` | `outputs/dualguard_mppi/{runs,matlab}` |
| `reachset_recording` | `experiments/reachset_recording/` | `outputs/reachset_recording/` |

`generate-raceline` (root pipeline) and `reconstruct_track` (dualguard_rc)
produce the shared inputs the sweeps consume.

## Running

```bash
uv sync                     # creates the venv and editable vendor installs
# This copy is code-only: data/ inputs and outputs/ results are not included.
# Supply the inputs (or configure a DVC remote) before running dvc repro.
uv run dvc repro            # root pipelines (reachset, controller, dualguard_rc, recording)
uv run dvc repro experiments/dualguard_mppi/dvc.yaml   # separate baseline pipeline
```

Experiment entry points run as modules so the path shim is installed first:

```bash
uv run python -m experiments.reachset_sweep.reachset_sweep --help
uv run python -m experiments.controller_sweep.controller_sweep --help
uv run python -m experiments.dualguard_mppi.scripts.rc_car_jax --help
```

## Import paths

`_paths.py` is the only place that manipulates `sys.path`. It adds `core/`,
`vendor/Buzzracer/buzzracer/` (for Buzzracer's `from common import *`),
`experiments/shared/` and each experiment directory, and
`experiments/__init__.py` installs it for every `python -m experiments.*`
invocation. The Buzzracer checkout imports `immrax_controller`,
`replay_controller` and `warehouse_track` by bare name, so those module
filenames must not change.

Core modules and shared helpers are imported as top-level modules
(`import immrax_planner`, `import _env`), not through a package. The shared
helper directory is named `shared` rather than `common` so it cannot shadow
Buzzracer's `common.py` on `sys.path`.
